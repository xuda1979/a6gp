## 安全与执行边界

每个 ACN 服务变更均通过 `prepare → authorize → commit`，执行器检查正在提交的动作、精确参数、R1 风险/T2 时间等级、任务租约和资源观测时效。直接调用服务的变更方法也必须具备匹配的提交中事务。注册、域间协议和资源观测属于宿主控制面输入，不能通过工具参数自行创建。

群组和计算使用同一上下行容量预算。预留以合同、租约、成员注册等有效期为上界；到期预留不再占用准入预算。已撤权任务的既有预留采用保守保留至到期的方式处理，不在确认真实资源状态前自动重分配。更新失败、版本陈旧或资源不足均不会覆盖已有有效预留。

群组 QoS 为输入网络模型下的准入约束。`DEGRADED` 表示新观测已不满足原准入条件，供上层重新规划；它不表示服务已自动完成无线修复。计算返回 `predictedTotalMs` 和 `predictedCost`，不会将资源预留回执解释为推理任务完成。

## 运行与接入

```bash
npm run check
npm run demo:acn
```

`examples/acn-lab.ts` 明确构造合成输入；`examples/acn.ts` 完成能力发现、组网、卸载准入和数据共享，并先证明缺少证据时合同保持 BLOCKED，再使用独立探针身份的模型状态断言完成软件验收。探针与服务仍在同一进程中，不能代替独立部署的网络测量。

宿主可通过 `createACNRuntime(existingNetworkExecutor)` 保留原 RAN/Core 适配器，通过 `NetworkToolGateway` 调用服务。`TaskAccess` 必须由认证后的宿主建立。外部调用建议使用 `callEnvelope`：由宿主查询受信任公钥，验证身份和关键扩展后进入同一网关；注册表里的端点字符串本身不建立真实网络连接。

`handleNetworkToolRPC` 实现 `tools/list`、`tools/call` 消息桥接，沿用 [MCP tools 消息结构](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。宿主 MCP Server 仍负责初始化、传输、认证和密钥。资源范围和幂等键通过 `params._meta.a6gp` 提供，身份和租约来自宿主上下文，不能从工具的 `arguments` 接受。

新增扩展与迁移规则见 [协议规范附录](../protocol/A6GP_SPEC_v0.4_BILINGUAL.md#acn-services-v1-extension--acn-服务扩展)。附件中的标准化进展仅作为历史材料，本文件不据此声称当前标准组织已采纳本实现。
