# A6GP 项目进展报告：ACN 服务能力与安全执行闭环

**报告日期：** 2026-10-23

**当前版本：** A6GP Core v0.4 + ACN Services v1 参考扩展，软件包 `0.4.1`

**本次依据：** 附件《智能体通信网络（ACN）——6G网络新变革》、仓库实现与本轮实际运行的验证结果

## 关键结论（Take-home points）

1. **项目已形成“网络服务智能体、智能体按意图调用网络能力”的双向软件闭环。** 在原有安全执行底座上，新增注册发现、跨域端点解析、动态群组、通算联合准入、数据生命周期和结构化任务编排，覆盖附件中连接、赋能、管理的主要功能要求。
2. **本次交付包含可运行代码与回归证据。** 现有 28 项测试全部保留，新增 46 项 ACN 测试，共 **74/74 通过**；7 份 Schema 语法检查及 14 项工具与 Schema 的一致性检查通过。体育场、ACK 丢失、ACN 协作示例均通过。
3. **新增服务沿用原有权限、事务和证据要求。** 资源变更必须绑定具体任务、租约和精确动作；撤权、陈旧观测、越权访问及资源不足均会阻止操作。服务执行成功后，合同仍需证据验收才能完成。
4. **当前证据支持软件原型可运行，下一步重点是设备与数据接入。** 本轮使用合成网络和算力输入；真实无线 QoS、推理执行时延、跨域可达性和生产环境可靠性仍需实验网验证。

## 1. 本次实现的能力

| 方向 | 已完成工作 | 解决的具体问题 |
|---|---|---|
| 智能体连接与发现 | 多厂商能力注册、按能力查询、注册过期处理、租户隔离、显式域间协议及 HTTPS 端点解析 | 任务可以找到合适的协作对象，并限制跨域访问范围 |
| 动态群组与新流量 | 表达七类信息模态及东西向/南北向流量；群组创建、修改、释放均有版本控制；按上下行带宽、时延、抖动、丢包和同步偏差准入 | 为每个任务配置群组服务条件，避免静态配置和重复预留；链路条件恶化时可识别群组降级 |
| 通算联合准入 | 在同一容量账本中协调群组带宽和计算卸载；联合考虑传输、排队、计算、内存、期限及成本 | 避免只看到空闲算力，却忽略传输开销或已占用带宽；选择满足约束的节点并预留资源 |
| 数据生命周期 | 有界字节数据捕获、顶层 JSON 字段脱敏、存储、共享、删除和保留期处理；记录哈希与处理谱系 | 支持多智能体共享经过处理的数据，并保留来源及权限依据 |
| 身份与动态授权 | 用户关联、身份/租约 ID 防覆盖、任务绑定租约、受限委托、撤权校验、操作及数据读取权限 | 防止同一租约跨任务复用，约束协作和数据访问边界 |
| 意图驱动与工具化 | 结构化协作意图分解为依赖图；提供 14 项工具、MCP tools 消息桥接及签名工具调用入口 | 将目标落实为有顺序、可检查的服务操作，并保留原有 RAN 适配器路径 |

## 2. 可复现的协作流程

新增示例从一个结构化协作意图出发，自动发现具备所需能力的成员，并执行六步操作：建立群组、预留计算资源、捕获数据、脱敏处理、存储、授权共享。依赖图校验后按顺序执行，遇失败或 UNKNOWN 时停止后续操作。

本轮合成示例成功选择基站侧计算节点，共产生 **6 次服务状态变更**；共享对象进入 SHARED 状态，探针逻辑确认指定字段已删除。缺少证据时，合同保持 BLOCKED；加入独立探针身份的模型状态断言后，各动作完成验收，合同进入 COMPLETED。

示例中的卸载时延为 **25 ms 预测值**：由固定链路开销、抖动、排队、计算与传输时间相加得到。该值用于检查准入算法及单位换算，**不属于设备实测，也不能据此判断已经达到附件提出的 10～20 ms 确定性时延目标**。探针和服务当前运行在同一进程，后续需要独立部署的遥测和测量系统。

| Schema 与工具契约 | 7 份语法检查、14 项目录一致性检查通过 | 工具输入的范围、数值、版本及状态约束另由运行时代码检查 |
| 可执行示例 | 3 个均通过 | 体育场任务、ACK 丢失对账、六步 ACN 协作 |
| 运行环境 | Node.js 22.23.4、24.19.0 验证通过 | 本地执行结果；远端 CI 结果以对应 PR 检查为准 |
| TypeScript | 严格类型检查通过 | 覆盖运行时、ACN 示例和两组测试 |

本轮特别验证了几个容易影响正确性的情形：两个并发群组争用同一上行资源时，只允许可容纳的预留成功；失败的群组更新保留原有资源；授权后撤权或观测过期会阻止提交；ACK 丢失时先对账并确认只产生一次副作用；链路容量下降后群组读数转为 DEGRADED，供上层重新规划。

复现命令为 `npm run check`，单独运行新流程使用 `npm run demo:acn`。本轮版本指纹及结果摘要见 [验证记录](ACN_Validation_2026-10-23.json)。测试通过表明已编码约束成立，不构成生产安全认证或实网性能结论。

## 4. 当前成熟度

当前交付具备完整的软件接口和内存原型，适合进入受控实验环境。以下能力仍需补齐：

- **真实网络与算力执行。** 群组 QoS 当前依靠输入模型准入，计算接口完成节点选择和预留；真实承载配置、模型任务启动及完成测量需要适配器支持。
- **长期运行和分布式可靠性。** 状态目前保存在单进程内存中。需持久化合同、租约、预留、幂等记录、数据对象和 UNKNOWN 对账状态，再验证重启与网络分区恢复。
- **外部协议与身份体系。** 已有 MCP 工具消息桥接、端点解析和签名入口；完整 MCP/A2A 传输、生产身份签发、可信密钥查询和跨运营域联邦仍待接入。
- **智能策略与效果评估。** 现有规划采用结构化输入和确定性规则。自然语言意图理解、在线学习和网络优化策略可由外部模型接入，仍须经过权限、预检和证据链验证。

## 5. 下一阶段优先事项

**第一，贯通一条真实实验链路。** 选定受控 RAN/边缘环境，先接入一个群组服务动作和一个计算任务，形成“观测—准入—下发—执行—测量—验收”的可重复流程。优先明确设备接口、观测字段、回退条件和测量口径。

**第二，补齐持久化与故障恢复。** 保证进程重启后恢复预留和动作身份，加入设备超时、链路分区、容量变化、撤权和 ACK 丢失等故障注入，重点验证重复副作用、资源泄漏及恢复正确性。

**第三，建立对照评估。** 比较直接工具调用、完整 A6GP 及关键机制消融，测量任务达成率、非授权操作、资源冲突、恢复时间、P95/P99 控制时延和每个成功任务的开销。确认收益后，再形成标准研究贡献及论文结论。

近期最需要落实的输入是实验平台、首批可控动作与 KPI，以及网络/算力适配和独立遥测的协作接口。这些输入决定下一阶段能否从软件语义验证推进到可量化的网络效果验证。
