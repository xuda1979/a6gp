# A6GP 项目进展报告：面向 6G Agentic RAN 的安全执行底座

**报告日期：** 2026-10-23  
**当前基线：** A6GP v0.4（主线最近一次发布提交：2026-10-05）  
**项目定位：** 面向 6G RAN 及跨域网络协作的 Agent 原生协议研究与参考实现

> **报告口径：** 本报告依据仓库主线代码、技术规范、测试说明、示例和路线图整理。仓库最近一次 GitHub Actions 一致性检查于 2026-10-05 成功；文中测试数量和演示结果来自仓库记录。当前材料覆盖协议与软件原型，不代表真实无线网络测试结果。

## 关键结论（Take-home points）

1. **项目已从协议构想推进到可运行的软件原型。** A6GP v0.4 同时具备协议规范、参考运行时、6 份 JSON Schema、28 项一致性测试和可复现的示例流程。
2. **方案针对 Agent 控制真实网络时的关键风险建立了闭环。** Agent 提出意图和动作，确定性运行时负责权限校验、动作授权、提交、异常对账和独立证据验收；这为 Agentic RAN 提供了可审计的执行边界。
3. **现有验证证明的是软件语义和模拟流程。** 仓库尚未包含真实 O-RAN/RAN 网元适配、外场测试或与其他实现的互操作结果，也尚未发布相对基线的性能数据。
4. **下一阶段应把资源集中到实验验证。** 先接入受控 RAN 测试环境并完成故障注入，再以统一指标与直接工具调用等基线进行对照，形成可支持技术决策的量化证据。

## 1. 项目目标与当前定位

A6GP（Agent-Native 6G Protocol）定义了自治 Agent 面向网络资源提出目标、获得受限授权、执行变更并证明结果的协议语义。其研究范围覆盖 RAN、核心网、传输、边缘和云；当前最适合优先验证的入口是 **Agentic RAN 控制**。

架构将开放式推理与确定性执行分层：Agent 可以负责目标理解、跨域协商和候选策略生成；协议运行时校验合同、权限和网络状态，并控制动作提交与结果验收。极低时延闭环继续由确定性策略或本地执行器承担。

A6GP 当前标注为 **Research Draft v0.4**，属于预标准研究规范。仓库将其定位为可与现有标准和接口衔接的研究控制层。

## 2. 已完成工作

| 工作方向 | 当前进展 | 对 Agentic RAN 的意义 |
|---|---|---|
| 意图与权限 | 定义 Intent Contract、租户和资源范围、分级权限租约、受限委托及撤销传播 | 将“优化目标”和 Agent 可操作的资源边界表达为可校验对象 |
| 安全动作事务 | 实现 prepare、authorize、commit、reconcile 与 compensation；授权绑定精确动作哈希、合同版本、拓扑、策略和前置条件 | 缩小计划生成与真实网络变更之间的风险窗口 |
| 故障与恢复 | 对重复请求提供逻辑幂等；外部结果不明确时进入 UNKNOWN 并对账，避免盲目重试 | 覆盖 ACK 丢失、控制器重试等网络控制常见异常 |
| 结果验收 | 支持独立证据门和证据冲突检测；合同完成需要满足证据要求 | 将“命令已接受”与“网络目标已达到”分开验证 |
| 高风险与快速控制 | 定义 R0–R3 风险等级、T0–T4 时间等级、R2/R3 预检和 R3 多方授权；包含 T0/T1 策略制品语义 | 支持不同风险和时延下采用相称的控制流程 |
| 协议与一致性工具 | 提供 v0.4 版本/配置协商、签名 Envelope、重放防护、6 份 Schema 和 5 类一致性 Profile | 为后续实现对接与互操作测试提供共同检查项 |

## 3. 当前 RAN 示例说明了什么

仓库提供两个可执行场景，展示协议闭环如何映射到 RAN 任务：

- **体育场馆容量优化场景：** 示例合同要求将 AR 业务 P99 时延控制在 20 ms 以下，并设置丢包率、能耗变化等约束。流程覆盖资源观测、权限租约、数字孪生预检、动作授权、提交和两类独立证据验收。
- **ACK 丢失场景：** 模拟 RAN 参数动作可能已经执行、但确认消息丢失的情况。流程将状态标记为 UNKNOWN，随后按原动作身份对账；示例记录物理动作只应用一次。

这些数值和结果属于仓库中的演示输入与内存执行器模拟，用于验证状态流转和协议语义，不能解读为真实网络 KPI 或现场性能结果。

## 5. 下一阶段建议

### 优先级一：接入受控 RAN 实验环境

以 O-RAN 或 srsRAN 类实验环境为入口，先选定少量边界清楚的动作，例如 PRB 配比调整或切换偏置更新。第一轮采用仿真或隔离实验网，明确资源范围、回退条件和人工接管机制，再逐步扩大动作种类。

### 优先级二：补齐可靠运行所需组件

将合同、租约、动作记录、幂等记录、UNKNOWN 对账状态和证据持久化；加入拓扑陈旧、ACK 丢失、控制器重启和网络分区等故障注入。重点观察恢复正确性和运行状态能否完整追溯。

### 优先级三：建立可比较的量化基准

建议至少比较三组配置：直接工具调用、启用 A6GP 全流程、A6GP 消融配置。统一测量：

- 非授权或违反约束的动作比例；
- 重复副作用与 UNKNOWN 对账成功率；
- 故障恢复时间和回滚成功率；
- P95/P99 控制时延及 SLO 达成率；
- 每个成功目标的动作数、模型调用数和资源开销。

基准和实验清单应随代码发布，便于复核和复现。

### 优先级四：推进外部互通与规范化

在实验语义稳定后，冻结消息绑定和适配器契约，开展独立实现互通；同时为关键状态机补充属性测试或形式化模型，再形成面向标准研究的贡献材料。

## 6. 管理层需要明确的三项输入

为控制下一阶段范围并缩短验证周期，建议尽早确定：

1. **首选实验环境：** 可用的 O-RAN/srsRAN 测试平台、仿真能力及接入负责人；
2. **第一批动作与业务目标：** 例如 PRB 配比或切换偏置，以及主要 KPI、硬约束和回退阈值；
3. **验证资源：** RAN 适配、测试与遥测数据所需的工程投入和协作边界。

## 总结

A6GP v0.4 已形成面向 Agentic RAN 的协议与参考运行时基础，核心贡献集中在受限授权、可控提交、异常对账和证据验收。现阶段最有价值的推进方向，是将这些机制接入受控 RAN 测试环境并用统一基准验证其效果。项目后续判断应以真实适配、故障恢复数据和对照实验结果为依据。
